# Typed DateTimeFormatter for date and datetime columns

Admitted as milestone `GV-001`. The milestone file is the executable contract.

## Decision

Add typed `DateTimeFormatter` to `grid-view-spec` for date and datetime columns across backend (Python/Jinja SSR) and frontend (TypeScript/AG Grid), following the existing pattern of `CurrencyFormatter`.

## Contract

This Contract records the Product Owner's resolved temporal and presentation rules for independent OMP verification. The task has no separate parent phase or required predecessor in the active `gridviewspec/plans/` scope. Preserve the existing task identity, active status, and delivery route; the gate lines below do not substitute for OMP admission before Build.

### Contract claims and path

- **DT-1 — typed value owner:** Define `@dataclass(frozen=True) class DateTimeFormatter` and the pure `format_datetime_value(value: object, formatter: DateTimeFormatter) -> str` canonically in `src/grid_view_spec/types/date_time_formatter.py`, with `format: Literal["date", "datetime", "time", "iso"] = "datetime"`, `locale: str = "uk-UA"`, `timezone: str = "UTC"`, `empty_value: str = "—"`, `strict: bool = False`. Re-export the type and function from `src/grid_view_spec/types/formatters.py` and expose the public type through `src/grid_view_spec/types/__init__.py` and `src/grid_view_spec/__init__.py`. The Jinja binding uses the canonical helper; `formatters.py` contains no second implementation. No process-global locale or timezone mutation, DB imports, network calls, or persistence.
- **DT-2 — temporal values and display:** The pure function accepts native `datetime.datetime`, `datetime.date`, `datetime.time`, valid ISO 8601 date/time/datetime strings, and finite Unix epoch numeric values. For each epoch value, use milliseconds when `abs(value) >= 1e11`, otherwise seconds. Project aware datetimes and epochs into `ZoneInfo(formatter.timezone)`; interpret naive native and ISO datetimes as UTC first. Preserve date-only and time-only components without artificial shifts; date-only as `time` and time-only as `date` are invalid. A date-only value formatted as `datetime` adds `00:00:00` to its unchanged date; formatted as `iso` it emits `YYYY-MM-DD` without a time or offset. A time-only value formatted as `datetime` is invalid; formatted as `iso` it emits `HH:mm:ss` without date or offset. For instant-bearing datetime/epoch inputs, `iso` emits offset-bearing ISO 8601 in the target timezone (`Z` for UTC), with at most three fractional-second digits. Localized `date`, `time`, and `datetime` use exact `uk-UA`/`de-DE` date `DD.MM.YYYY`, `en-US` date `MM/DD/YYYY`, 24-hour `HH:mm:ss`, and a space between date/time; unsupported locales follow `uk-UA`. `None` and empty strings return `empty_value` in both modes. With `strict=False`, invalid or out-of-range values, invalid timezone, and invalid format return `empty_value` without raising; with `strict=True`, invalid/unparseable values, invalid timezone, and invalid format raise `ValueError`. Valid ISO strings remain accepted in strict mode.
- **DT-3 — wire/public boundary:** Add `date_time_formatter: DateTimeFormatter | None = None` to `GridViewColumn` in `src/grid_view_spec/types/table_v2.py`. Recursive `spec_to_wire` emits snake_case fields; decode the optional snake_case formatter in `src/grid_view_spec/wire_decode.py`, preserving absent/null as `None` and valid fields exactly. A present malformed formatter object or wrong-typed member is rejected by `spec_from_wire` with `INVALID_WIRE` rather than silently dropping bad page/block input (`src/grid_view_spec/validate/__init__.py:18-28`). Do not reuse currency's `formatter` alias; do not change currency decode. The two mirrored JSON schemas (`schema/grid-view-spec.v2.json` and `src/grid_view_spec/schema/grid-view-spec.v2.json`) currently type table `columns` as an unconstrained array (`:545-586`); no schema-key change is required unless independent verification demonstrates a validation mismatch.
- **DT-4 — SSR:** Bind `format_datetime` in `src/grid_view_spec/render/bind.py` and `src/grid_view_spec/render/spec_renderer.py`; apply it in `src/grid_view_spec/templates/grid_view/spec/table.html` to configured date/datetime row **and footer** cells before generic null/empty handling, so configured `empty_value` survives. Preserve autoescaping for both formatted content and existing unconfigured cells; keep currency, inline editing, and non-date render paths unchanged.
- **DT-5 — AG Grid:** Emit a camelCase `dateTimeFormatter` object only for configured date/datetime columns in `src/grid_view_spec/render/ag_grid.py`; type and forward it through `AgGridSpecColumn` / `buildColumnDefsFromSpec` in `frontend/src/runtime/table-ag-grid.ts`. Select it for configured date/datetime columns, preserving explicit custom renderer selection and the unconfigured `date` builtin. Validate config and use `Intl.DateTimeFormat` for locale and target-zone components, assembling the exact date/time/datetime output layouts in DT-2 and matching Python's visible component order, separators, and 24-hour clock; unsupported locales use `uk-UA`. For instant-bearing inputs, `iso` emits target-zone offset-bearing ISO (`Z` for UTC, at most milliseconds); date-only `iso` remains date-only and time-only `iso` remains `HH:mm:ss`. On AG Grid even with `strict=True`, malformed values, invalid date/time component combinations, invalid timezone, or corrupt config render escaped effective `emptyValue` without an unhandled exception; empty values render it in either mode. Escape displayed text and preserve script containment. Dynamic column-source JSON uses the same builder; externally supplied `columnsVar` column definitions remain host-owned and are not rewritten.

### Product Owner decisions

1. **Locale inventory & formatting engine**:
   - Supported named locales: `uk-UA`, `en-US`, `de-DE`.
   - Unsupported locales fall back to `uk-UA` formatting, not ISO.
   - Implementation: pure Python stdlib pattern mapping (`uk-UA`/`de-DE`: `DD.MM.YYYY`, `en-US`: `MM/DD/YYYY`; 24-hour `HH:mm:ss`; datetime joins date and time with one space), without mutating global process locale or adding external packages.
2. **Timezone behavior**:
   - Use `zoneinfo.ZoneInfo`. Invalid/unsupported timezone: raises `ValueError` when `strict=True`, returns `empty_value` when `strict=False`.
3. **Unix epoch units**:
   - Both seconds and milliseconds supported: values with `abs(value) >= 1e11` are treated as milliseconds; smaller magnitudes as seconds.
4. **Strict mode semantics**:
   - When `strict=True`: raises `ValueError` on unparseable/invalid inputs, invalid timezone/format.
   - When `strict=False`: returns `empty_value` with zero-exception safety (never crash SSR or AG Grid).
   - `None` and empty strings return `empty_value` in both modes.
5. **Naive datetime interpretation**:
   - Naive `datetime` instances and naive ISO strings are assumed UTC before timezone projection.
6. **Date-only and time-only values**:
   - Preserved without artificial date/time shifts. Requesting date-only as `time` or time-only as `date` is invalid (raises in strict mode, returns `empty_value` in non-strict).
7. **ISO normalization**:
   - For instant-bearing datetime/epoch input, `iso` emits offset-bearing ISO 8601 in the target timezone (`Z` for UTC), with fractional seconds capped at milliseconds (3 digits). Component-only ISO follows the explicit rules in the presentation resolution below.

### Product Owner resolution for presentation & JS error boundaries

1. **Unsupported locale and display**:
   - Exact fallback: unsupported locales fall back to `uk-UA` formatting (`DD.MM.YYYY`, 24h `HH:mm:ss`).
   - Exact patterns:
     - `uk-UA`: date `DD.MM.YYYY`, time `HH:mm:ss` (24h), datetime `DD.MM.YYYY HH:mm:ss`.
     - `de-DE`: date `DD.MM.YYYY`, time `HH:mm:ss` (24h), datetime `DD.MM.YYYY HH:mm:ss`.
     - `en-US`: date `MM/DD/YYYY`, time `HH:mm:ss` (24h), datetime `MM/DD/YYYY HH:mm:ss`.
     - Python output matches these standard component layouts.
2. **Strict JS invalid inputs**:
   - AG Grid client cell renderers MUST NEVER throw unhandled exceptions (zero-exception UI contract). When `strict=True` on client-side AG Grid, invalid values or corrupt configs render escaped `emptyValue` safely without throwing.
3. **Component-only `datetime`/`iso`**:
   - `date-only × datetime`: renders date plus `00:00:00`.
   - `date-only × iso`: emits `YYYY-MM-DD` without artificial time/offset components.
   - `time-only × datetime`: invalid input (returns `empty_value` in non-strict, raises in strict).
   - `time-only × iso`: emits `HH:mm:ss` without artificial date components.
